# 使用 no-negative-echo

[English](../en/usage.md) · [接入宿主](harnesses.md) · [README](../../README.md)

先安装完整技能或按接入指南提供规则正文。在任务里说明要完成的结果、必要材料和验收条件；宿主加载 `SKILL.md` 后按场景选择模块。中文会话使用 `zh-CN`，其他会话默认使用 `en`。

## 从一个任务开始

```text
使用 no-negative-echo 为以下工具写一段面向使用者的介绍：
工具每天备份本地目录，只存储变更块，支持按日期恢复。
读者需要理解功能、方法和用途；约 80 字。
```

可接受的示例成稿：

> 支持本地目录每日增量备份，按变更块保存数据，减少重复存储；可按日期恢复，方便找回所需版本。

检查：三项已知功能保留；收益与给定机制相连；量化承诺有数据来源。这个示例用于解释验收方法，实际输出可以有不同措辞。

## 按任务使用

| 任务 | 输入需要包含 | 结果检查 |
|---|---|---|
| 回答与纠正 | 当前问题、确认后的事实或约束 | 回答切中问题，后续结果应用纠正 |
| 持续协作 | 已授权范围、目标产物、验收条件 | 推进授权范围内的工作；进展和完成程度有证据 |
| 对外成稿 | 读者、文体、已实现功能、测量或使用证据 | 清楚呈现成果、方法和收益，准确说明适用范围 |
| 根因修复 | 最小复现、预期行为、可访问源码和测试 | 修复产生问题的位置，同步实现与说明，实际路径验证通过 |

例如工程任务：“修复任务状态不同步，检查状态来源和更新路径，验证启动、停止及状态读取。”在连续纠正中直接补充新事实，例如“任务状态由服务端返回；以服务端为唯一来源”，让后续实现和说明统一应用它。

## 控制读取范围

入口路由到四组中英文模块，一次任务可组合使用。对普通问答只读表达模块；交付文稿时加入成稿模块；涉及代码时加入工程模块；执行工具任务时加入协作模块。相对路径从技能目录解析。

文本扫描器按明确词项检查内容和文件名，适合检查已知遗漏。运行 `python /path/to/no-negative-echo/scripts/check_surface.py --help` 查看接口。语义、事实和任务是否完成仍需结合实际产物判断。

## 反馈、升级与恢复

反馈包含技能版本、宿主与模型、调用方式、最小输入、实际输出和期望行为；敏感数据先做脱敏。行为用例可参考 [evals](../../evals/evaluation-protocol.md)。

升级前保存自己的修改，并保留发现目录之外的旧版副本。使用对应版本的 [INSTALL.md](../../INSTALL.md) 安装，新会话中重复代表性任务。发现冲突时先比较文件；恢复步骤见[维护指南](maintenance.md)。
